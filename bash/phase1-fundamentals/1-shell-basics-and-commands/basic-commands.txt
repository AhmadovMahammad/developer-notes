1. `cd` - Change Directory

This command is used to move between folders (directories) in the file system.

But let’s go deeper. The terminal session always has a concept of a current working directory - that’s the directory you're "inside" when you type a command.

The `cd` command modifies this current directory.

cd /home/mahammad/Downloads

This changes your current path into the `Downloads` folder.
So if you now run `pwd`, it will show: /home/mahammad/Downloads

-_-

You can use: cd ..

This moves you up one level. If you're in `/home/mahammad/Downloads`, `cd ..` takes you to `/home/mahammad`.

The `..` means “parent directory”.

-_-

You can also use: cd ~

This will always take you to your home directory, such as `/home/mahammad`.

And, cd with no arguments does exactly the same - go to your home directory.

-_-

Now, one very useful trick:

cd -

This goes to the previous directory. Think of it as an undo.

Let’s say:

```
cd /etc
cd /var/log
cd -
```

You will be taken back to `/etc`.

2. `ls` - List Directory Contents

This command is used to see what’s inside a directory.
But there’s a lot more under the surface.

Basic usage: ls
lists the contents of the current directory.

If you do: ls foldername => it lists what’s inside that folder.

-_-

But `ls` has very useful flags:

```
ls -l
```

This gives you a long format listing, showing:

```
drwxrwxr-x 5 mahammad-ahmadov mahammad-ahmadov 4096 Jun  4 18:33 phase1-fundamentals
```

This tells you the file is:

[1]  drwxrwxr-x  
[2]  5  
[3]  mahammad-ahmadov  
[4]  mahammad-ahmadov  
[5]  4096  
[6]  Jun  4 18:33  
[7]  phase1-fundamentals


[1] drwxrwxr-x
This is file type + permissions - it has 10 characters.

First character: d = directory. If it's -, it's a regular file.
The next 9 characters are permissions, in 3 groups:

rwx  rwx  r-x
│     │     │
│     │     └── others
│     └──────── group
└────────────── owner

Owner: rwx = read, write, execute → 7
Group: rwx = read, write, execute → 7
Others: r-x = read, no write, execute → 5

write = 2
execute = 1
read = 4


[2] 5 - What is this number?
This is the link count - the number of hard links pointing to this directory.
At the end, there is detailed information about LINKS

-_-

Another important flag:

```
ls -a
```

This shows all files, including hidden files (those starting with a dot `.` like `.bashrc` or `.git`).

You can combine flags:

```
ls -la
```

or

```
ls -lh
```

Here `-h` gives “human-readable” file sizes like `5K`, `2M`, etc.

To list directories only:

```
ls -d */
```

This is advanced, but very useful.
Let’s look at how it works:

This command looks short, but under the hood, it's a combination of two key things: 
1. how globbing (`*`) works and 2. how `ls -d` behaves.

Let’s break it fully:
  
-_-

What does `*` mean?

In Bash, `*` is a glob pattern. 
It expands to match any filename or folder name in the current directory. 
For example, if you have:

```
file1.txt
folder1/
script.sh
data/
```

Then `*` expands to:

```
file1.txt folder1 script.sh data and the children of subdirectories
```

-_-

What does `*/` mean?

This is also a glob, but with a trailing slash.

This means:
match anything (`*`) that is a directory (`/`).

So `*/` matches:

```
folder1/
data/
```

It will not match `file1.txt` or `script.sh`, because those are not directories.
if we have written it like *.txt, it would show files with .txt extension.

-_-

What does `ls -d` do?
Normally, when you run:

```
ls folder1
```

You get the contents inside `folder1`.

But when you run:

```
ls -d folder1
```

You don’t get what's inside. You get the folder name itself.
So `-d` means: don’t go inside the directory, just treat it like a file and show its name.

-_-

Putting it all together

```
ls -d */
```

Here's the full logic:

1. `*/` is expanded by Bash into a list of directory names, like:

   ```
   folder1/ data/
   ```

2. `ls -d` receives this expanded list and says:
   “Don’t go inside these directories. Just list their names.”

So the output is a clean list of only directory names in the current folder, like:

```
folder1/  data/
```

No files are shown. No contents of folders are listed.

This is a simple command that tells you your current location in the filesystem - the full absolute path.

For example: pwd

might return:

```
/home/mahammad/projects/bash-course
```

4. `mkdir` - Make Directory
This command creates folders.

Basic usage: mkdir new_folder

creates a folder in the current directory.

But if the parent folder doesn’t exist, it will fail:

```
mkdir a/b/c
```

will fail if `a` or `a/b` doesn't exist.

To fix that:

```
mkdir -p a/b/c
```

The `-p` flag tells it to create parent directories as needed.

This is very useful in scripts.

1. If the folder already exists:
without `-p`, you’ll get an error:

```
mkdir: cannot create directory ‘a’: File exists
```

2. with `-p`, it will silently skip creating it again.

So always use `-p` when you're not sure the folders exist or not.

-_-

Also:

```
mkdir -v foldername
```

prints what it creates:

This is optional but useful for logging or scripts.

5. What `rm` really does

The real nature of files in Linux

In Linux (and Unix systems), a file is not just its name. 
The name is only a label stored in a directory entry - it maps to something deeper called an inode.

An inode is a data structure that contains:

* metadata: permissions, ownership, size, modification time
* a list of blocks (disk locations) where the actual content (the file's data) lives

The file name itself is not stored inside the inode. 
The name only exists in the directory that contains the file. This is crucial to understand.

So in reality, your file system works like this:

```
Directory entry: "file.txt" → inode 12345 → actual content
```

What does `rm` actually do?

When you run:

```
rm file.txt
```

Linux looks up `file.txt` in the current directory. It finds that this name points to inode 12345 (for example). 
Then, `rm` removes the name from the directory. That’s all.
The inode 12345 is now no longer referenced by this name.

Now comes the important part:
When is the inode (and file content) deleted?

Linux keeps a reference count inside the inode. This count tells: how many names (directory entries / hard links) point to me?
If the count drops to zero - meaning no names point to the inode anymore, and no program is keeping the file open, 
then the system knows the file is truly unreachable, and it frees the disk space.

But if you had another hard link pointing to the same inode, like this:

```
ln file.txt second_name.txt
```

Then both `file.txt` and `second_name.txt` point to inode 12345. Deleting just one:

```
rm file.txt
```

doesn’t destroy the content. It only removes one label. The data lives on via the second name.
Only when you remove all links to the inode, the system cleans it up.

-_- Are files moved to trash?

No. `rm` does not move files to trash or recycle bin. There is no built-in undo.

Graphical interfaces (like GNOME or KDE) simulate trash by moving files to `~/.local/share/Trash`, but `rm` bypasses all that. 
It talks directly to the file system. It unlinks the directory entry.

So recovery is difficult unless:

* You shut down the system quickly to prevent disk overwrite
* You use specialized inode-recovery tools (low chance of success)
* You had backups

-_-

`-i` (interactive)
Before removing each file, ask for confirmation.

```
rm -i important.txt
```

Terminal will ask:
`rm: remove regular file 'important.txt'?`
This prevents accidental deletions.

-_-

`-f` (force)
This forces deletion - even if the file is write-protected, or doesn't exist (no error). It disables any prompt.

```
rm -f dontcare.txt
```

This is dangerous if used alone or in scripts.

-_-

`-r` or `-R` (recursive)
This is how you delete directories and everything inside them (files and subdirectories).

```
rm -r myfolder/
```

This walks through the directory tree and removes everything it finds.
If you don’t use `-r`, you cannot delete a directory.

-_-

`-rf` (recursive + force)

```
rm -rf myfolder/
```

This is the most dangerous version. It:

* Deletes everything inside `myfolder`
* Does not ask for confirmation
* Ignores errors

It’s powerful in scripts, but risky in real terminal work.

-_-

Example for combined usage
Imagine you have a folder `old_project` with lots of nested folders and protected files. This command:

```
rm -rf old_project
```

will silently wipe the entire folder tree in one go. No undo.

-_-

Some tips and best practices

* Use `-i` or `-I` (capital i, less intrusive) if you want safety
* Always double-check the path before using `rm -rf`
* Never run `rm -rf /` or `rm -rf *` without thinking
* Use `echo` before running: `echo rm -rf myfolder` to verify you typed it right

The cp Command - Making Copies

The name cp stands for "copy". When you copy a file, you're creating a completely new file with the same content as the original.

Think about it like photocopying a document in real life. You have one piece of paper. 

You put it in the machine. Now you have two pieces of paper. They look the same, but they are separate. 

If you burn one, the other is still fine.

That's exactly what cp does.

Basic Usage

cp file.txt backup.txt

This creates a new file called backup.txt that contains everything from file.txt.

Now you have two separate files. They are not connected at all. If you change file.txt later, backup.txt stays the same. 

If you delete one, the other remains.

What Really Happens Inside Your Computer

Every file on your computer has two parts:

    The name - what you see when you list files: file.txt
    The actual data - the content stored on your disk

Behind the scenes, your operating system uses something called an inode to keep track of files. 

Think of an inode as an ID card for a file. It contains information like:

    Where the file's data is stored on the disk
    How big the file is
    When it was created and modified
    Who owns it
    What permissions it has

The file name is just a label that points to this inode.

When you run cp file.txt backup.txt, here's what happens:

    The computer opens file.txt and finds its inode
    It creates a completely new inode for backup.txt - a new ID card
    It reads the content from file.txt chunk by chunk (usually 4096 bytes at a time)
    It writes those chunks into the new location for backup.txt
    It copies basic information like permissions

So cp creates:

    A new name: backup.txt
    A new inode: with its own ID number
    New space on disk: containing a copy of the content

The two files are completely independent. They have different inodes, different storage locations. 

Changing one doesn't affect the other at all.

Why This Matters

Because cp physically copies all the data, it:

    Takes time - copying a 10GB file means reading and writing 10GB of data
    Uses disk space - you now have two copies taking up space
    Creates independence - the files have no connection after copying

Copying Folders

If you try to copy a folder, you'll get an error:

cp myfolder newfolder

The error says something like:

cp: -r not specified; omitting directory 'myfolder'

This fails because cp needs to know: should I go inside the folder and copy everything in it?

You have to tell it explicitly by using the -r flag. The "r" stands for "recursive", 

which means "go inside and do this for everything you find, and if you find more folders, go inside those too".

cp -r myfolder newfolder

Now it works. It creates newfolder and copies every file and subfolder from myfolder into it. It recreates the entire structure.


-- Useful Options for cp

Recursive copy (for directories):

cp -r myfolder newfolder

Essential when copying folders.

Interactive mode:

cp -i file.txt existing.txt

If existing.txt already exists, it will ask you: "overwrite existing.txt? (y/n)". You type y for yes or n for no. This prevents accidents where you accidentally replace important files.

Verbose mode:

cp -v file.txt backup.txt

This shows you what it's doing. It prints messages like: 'file.txt' -> 'backup.txt'. Useful when copying many files so you can see progress.

Archive mode:

cp -a myfolder backup/

This is a special mode that preserves everything exactly: timestamps, permissions, symbolic links, ownership. It's like saying "copy this exactly as it is, don't change anything". Very useful for creating proper backups.

You can combine flags:

cp -av source/ destination/

This does archive mode and shows you each file being copied.

The mv Command - Moving and Renaming

The name mv stands for "move". But it does two things that might seem different at first: it moves files to new locations, and it renames files.

Actually, these are the same thing. Renaming a file is just moving it from one name to another in the same folder.
Basic Renaming

Type this:

mv oldname.txt newname.txt

The file oldname.txt disappears. Now you have newname.txt.

But here's the important part: the file itself wasn't touched. The content wasn't copied. The inode (the file's ID card) stayed exactly the same.

Think of it like this: you have a box with "Box A" written on it. You cross out "Box A" and write "Box B" on the same box. The box and everything inside it is exactly the same. You just changed the label.

That's what happens with mv when you rename a file. The operating system just updates the name that points to the same inode. The inode number doesn't change. The data doesn't move.

You can verify this. Type:

ls -i file.txt

This shows you the inode number. Let's say it shows:

12345 file.txt

Now rename it:

mv file.txt newname.txt

Check again:

ls -i newname.txt

You'll see:

12345 newname.txt

Same inode number! The file's identity didn't change. Only its name changed.

That's why renaming is instant, even for huge files. Nothing is actually moving. It's just a label change.
Moving to Another Location

Type this:

mv report.txt Documents/

This moves report.txt into the Documents folder. The file disappears from your current location and appears inside Documents.

If both locations are on the same filesystem (same hard drive partition), it's still just a label change. The inode stays the same. The computer just updates the directory information to say "this file is now in Documents instead of here".

Still instant. Still no data copying.



### Moving Across Different Filesystems

Here's where it gets different. Imagine you have an external USB drive or a separate partition on your hard drive. 

You want to move a file from your main disk to the USB drive:

mv /home/user/photo.jpg /media/usb-drive/

Now the computer can't just change a label. 

Why? Because different filesystems have completely separate inode systems. They don't share the same ID cards.

Your main disk has its own set of inodes. The USB drive has its own separate set of inodes. 

An inode number from one doesn't mean anything on the other.

So in this case, mv has to do this:

    Copy the entire file to the new location (creating a new inode there)
    Delete the original file from the old location

It's essentially doing cp and then rm (remove) behind the scenes.

That's why moving across different disks takes time, especially for large files. It's actually copying all the data.



### Renaming Folders

Same rules apply:

mv old-folder-name new-folder-name

If it's on the same filesystem, it's instant - just a label change.

If it's across different filesystems, it copies everything inside recursively (all files and subfolders), then deletes the original. 

This can take a very long time for large folders.

Important Warning About Overwriting

If you do this:

mv draft.txt final.txt

And final.txt already exists, it will be replaced without any warning. The old final.txt is gone forever. Deleted. No recovery.

This is dangerous. To be safe, use the -i flag:

mv -i draft.txt final.txt

Now it asks: "overwrite 'final.txt'? (y/n)". You can choose. If you type n, nothing happens. The command is cancelled.



### Useful Options for mv

Interactive mode:

mv -i oldfile.txt newfile.txt

Asks before overwriting anything. Very safe.

No clobber mode:

mv -n source.txt destination.txt

This means "never overwrite". If destination.txt exists, the command simply fails and does nothing. The existing file is protected.

Verbose mode:

mv -v file.txt new-location/

Shows you what was moved: 'file.txt' -> 'new-location/file.txt'

The touch Command - Creating Files and Updating Timestamps

The name touch is interesting. It doesn't mean "fill with content" or "open for editing". It means "touch the file's metadata" - specifically, its time information.

Every file on your computer has timestamps. Your operating system tracks:

    When the file was created
    When it was last opened
    When its content was last changed

These timestamps are stored in the file's inode (its ID card).



### Creating an Empty File

Type this:

touch notes.txt

If notes.txt doesn't exist, it creates an empty file. Not a file full of zeros or spaces - a truly empty file.

The operating system creates:

    A new inode (a new ID card)
    A name notes.txt pointing to that inode
    But no content blocks yet

The file exists, but it has zero bytes of content. You can check:

ls -lh notes.txt

You'll see something like:

-rw-r--r-- 1 user user 0 Dec 23 10:30 notes.txt

That 0 means zero bytes.

This is useful when you want to create a file quickly before putting anything in it. 

Or when you need a file to exist for a program to work with.



### Updating Timestamps

Now type this again:

touch notes.txt

The file already exists. So what happens?

Nothing visible. The file size doesn't change. The content doesn't change. But behind the scenes, 

the timestamps in the inode are updated to right now - this very moment.



#### Why Timestamps Matter

Many programs make decisions based on file timestamps:

Backup programs only back up files that changed since the last backup.

They check the modification time. 

If a file's timestamp is older than the last backup, it's skipped.

Build systems (like when compiling code) only recompile files that changed. 

They compare timestamps. 

If your source code is newer than the compiled program, they rebuild. If it's older, they skip it.

Cache systems expire old files. If a cached file hasn't been accessed in 30 days, delete it.

By using touch, you can trick these systems. 

You can make a file look "freshly modified" even if you didn't change anything inside it.



### Seeing Timestamps

Want to see these timestamps? Use the stat command:

stat notes.txt

You'll see output like this:

  File: notes.txt
  Size: 146             Blocks: 8          IO Block: 4096
Inode: 2279142          Links: 1
Access: 2025-06-06 17:42:12.031955961 +0400
Modify: 2025-05-27 23:41:06.320740396 +0400
Change: 2025-05-27 23:41:06.320740396 +0400
 Birth: 2025-05-27 23:39:43.662440310 +0400

Look at those time fields:

    Access: When the file was last opened or read
    Modify: When the file's content was last changed (data inside the file)
    Change: When the file's inode was last changed (metadata like permissions)
    Birth: When the file was first created (this never changes)

When you run touch notes.txt, it updates the Access and Modify times to the current moment:

  File: notes.txt
  Size: 146             Blocks: 8          IO Block: 4096
Inode: 2279142          Links: 1
Access: 2025-06-06 20:14:29.633280250 +0400
Modify: 2025-06-06 20:14:29.633280250 +0400
Change: 2025-06-06 20:14:29.633280250 +0400
 Birth: 2025-05-27 23:39:43.662440310 +0400

Notice that Birth stayed the same. That never changes. But Access, Modify, and Change all updated to the new time.



### A Real Example

Imagine you have a config file:

config.cfg

And a program that checks: "Has the config file been modified since I last read it? If yes, reload it."

But you didn't actually change anything. You just want to force the program to reload the config. You can do:

touch config.cfg

Now the file appears "freshly modified" even though the content is identical. The program sees the new timestamp and reloads.



### Useful Options for touch

-- Don't create if missing:

touch -c file.txt

This only updates the timestamps if the file already exists. If it doesn't exist, nothing happens. 

No file is created. Useful when you only want to update existing files.


-- Update only access time:

touch -a file.txt

Changes when the file was "last accessed", but leaves the modification time alone.


-- Update only modify time:

touch -m file.txt

Changes when the file was "last modified", but leaves the access time alone.

The cat Command - Displaying and Joining File Content

The name cat is short for "concatenate", which means "join things together". But most of the time, people use it just to display what's inside a file.


Basic Usage

cat notes.txt

Everything inside notes.txt gets printed to your screen. 

The file is opened, read from beginning to end, and all the content appears in your terminal.

The content doesn't stop or pause. It all appears at once. 

If the file has 1000 lines, all 1000 lines scroll past. You might only see the last screenful.



What "Standard Output" Means

This is important to understand because you'll see this term everywhere.

When you run cat notes.txt, where does the content go?

It goes to something called standard output. This is a technical term, but it just means "the default place where output appears".

Think of your terminal as having three channels:

    Standard input (stdin): Where commands read input from (usually your keyboard)
    Standard output (stdout): Where commands send normal output to (usually your screen)
    Standard error (stderr): Where commands send error messages to (also usually your screen, but separately)

These are like pipes. Data flows through them.

When you type cat notes.txt:

    cat opens the file
    Reads the content
    Sends it to standard output (the stdout pipe)
    Standard output connects to your screen by default
    So you see the content


But here's the powerful part: you can redirect these pipes. You can make standard output go somewhere else instead of your screen.


### 1. Redirecting Output to a File

cat notes.txt > output.txt

The > symbol is called a redirect operator. 

It says: "take everything that would normally go to standard output (your screen), and send it to this file instead".

So now the content of notes.txt doesn't appear on your screen. Instead, it's written into output.txt.

If output.txt already existed, it gets completely replaced. The old content is erased. If it didn't exist, it gets created.


### 2. Appending Instead of Replacing

cat more.txt >> output.txt

The >> symbol is different. It means "append to the end". 

So the content of more.txt gets added to the end of output.txt. The existing content in output.txt is kept.

This is very useful for adding to log files or building files gradually.


### 3. Joining Multiple Files Together

This is where the name "concatenate" makes sense.

Type this:

cat file1.txt file2.txt file3.txt

This reads file1.txt first, all the way to the end. Then it reads file2.txt, all the way to the end. Then file3.txt. 

All three are displayed one after another.

Now combine this with redirection:

cat file1.txt file2.txt file3.txt > combined.txt

Now combined.txt contains all three files joined together in order. First all of file1.txt, then all of file2.txt, then all of file3.txt.

This is the original purpose of cat - to concatenate (join) files.


### 4. Creating a File by Typing

Here's a neat trick. Type this:

cat > newfile.txt

Notice there's no filename before the >. What's happening?

cat is reading from standard input, which is your keyboard. And sending to standard output, which is redirected to newfile.txt.

So now your cursor is waiting. You can type whatever you want:

Hello
This is a test
I am typing directly

When you're done, press Ctrl + D. This sends an "end of input" signal.

Now newfile.txt exists and contains exactly what you typed. 

You just created a file from your keyboard without opening any editor.


### Useful Options for cat

Show line numbers:

cat -n file.txt

Every line gets a number on the left:

     1  First line
     2  Second line
     3  Third line

Very useful when you're looking at code or logs and you need to reference specific lines. 

You can say "look at line 47" and everyone knows exactly where to look.

The echo Command - Printing Text

The echo command does one simple thing: it prints whatever you tell it to print.

echo Hello

It prints:

Hello

That's it. But this simplicity is powerful when you understand how it works.

What Is Actually Happening

When you type echo Hello, here's the process:

    The shell (bash) sees the command echo with the argument Hello
    It runs the echo program
    echo receives the text Hello
    echo sends that text to standard output
    Standard output goes to your screen
    You see: Hello

Remember standard output from earlier? That's the default channel where output flows. 

echo is one of the simplest programs - it just takes input and sends it straight to standard output.


### Printing Variables

Your system has things called environment variables. These are like named storage boxes that hold information. Programs can look up these values.

For example, there's a variable called HOME that contains the path to your home folder.

echo $HOME

The $ symbol means "get the value of this variable". So the shell sees $HOME, looks it up, finds the value (like /home/john), 

and replaces $HOME with that value before running echo.

So if your home folder is /home/john, it prints:

/home/john


echo $USER

This prints your username. The shell looks up the USER variable and prints its value.


echo "My name is $USER and I live in $HOME"

It prints something like:

My name is john and I live in /home/john

The shell replaces both $USER and $HOME with their values before the text gets to echo.
How Quotes Work

This is important. There are two types of quotes, and they behave differently.

Double quotes " - Allow variable replacement

echo "Hello $USER"

The shell sees $USER, looks up its value, and replaces it. If your username is john, you see:

Hello john

Single quotes ' - Treat everything as literal text

echo 'Hello $USER'

The shell does NOT replace the variable. It treats $USER as literal characters. You see:

Hello $USER

The dollar sign is just a dollar sign. Nothing is looked up.

So use double quotes when you want variables to be replaced. 

Use single quotes when you want exact literal text.



You can use echo with redirection to quickly create or modify files.

echo "Hello World" > greeting.txt

This creates a file called greeting.txt with "Hello World" inside it.

Remember the > redirect operator? It sends standard output to a file instead of the screen. 

So echo prints "Hello World", but instead of going to your screen, it goes into greeting.txt.

If greeting.txt already existed, it gets completely replaced.

Now type this:

echo "Goodbye World" >> greeting.txt

The >> operator appends to the end. So now greeting.txt contains:

Hello World
Goodbye World

The first line is still there. The new line was added after it.

This is very useful for:

    Adding entries to log files
    Building configuration files line by line
    Creating simple test files quickly
